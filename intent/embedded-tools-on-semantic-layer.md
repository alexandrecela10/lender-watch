# Intent: a prototype of AI tools inside Excel and Claude, fed by agreed definitions

Author: Alexandre Cela, writing as the analyst who monitors a portfolio of PE funds. Status: draft, awaiting correction by the author.
Source: no opportunity analysis. This follows `intent/engine-in-excel-and-claude.md` and the design discussion of 11 November 2026.
Evidence: public filings for lender data. Everything about what an investor owns is synthetic, because no real holdings may be used. No LP or GP analyst has been interviewed. The pain is inferred.
Kind: prototype. It shows the idea works end to end. It is not for production use.

## Problem

- Lender Watch says a company's debt is marked down. It can't say how much of my money sits in that company, because it knows nothing about what I own.
- News between reports arrives as letters. A write-down in a manager's letter reaches no number until someone retypes it.
- When a figure moves between two dates, I rebuild the reason by hand.
- Each new measure today means new code in the tool. The rules for a flag live in the code, with no owner and no version.
- One case, from Alexandre's own 60-question test on synthetic data: the same question, "how exposed are we to one company", returned $105.66m, $26.27m, $3.83m and $8.06m across four setups. Only the setup with agreed definitions and one ID per company gave the right $8.06m.

## Proposed outcome

- **One tool, many measures.** I ask for a measure, a set of companies and a date, in an Excel formula or in Claude. A new measure is a new written definition, not a new tool.
- **Measures with an owner.** Each measure is written once in plain words, with an owner and a version. Code does the maths. The AI never produces a number.
- **Letter reader.** I give it a manager's letter. It proposes a dated event with the exact sentence it came from. Nothing changes until I confirm.
- **Change explainer.** I give it a measure and two dates. It says what moved and why, with each part linked to its source.

What should change:
- Measures defined outside the code, each with an owner and version: 0 today. Target: at least 6, of which at least 2 need the synthetic holdings.
- Same measure, company and date asked in Excel and in Claude, same number: unobserved. Target: all cases in a test set whose size is set in the spec.
- Events from letters that reach a number without retyping: 0 today. Target: measured against an answer key. The rate is unobserved.
- Events the letter reader proposes that are wrong: unobserved. Target: measured, and no event counts before a person confirms it.
- Parts of an explained change that add up to the total change: unobserved. Target: all of them, checked by code.
- Time to add one new measure: unobserved. Target: measured once, on a seventh measure.

What must not get worse:
- Everything in "must not get worse" in `intent/engine-in-excel-and-claude.md`.
- Invented figures attached to a real company: 0.
- Synthetic values shown without the word "synthetic": 0.

## Affected users and systems

Users: Alexandre, to show the idea. Later, an analyst who monitors funds, and a risk or data owner who signs off each definition.
Systems: the Lender Watch tool and its saved answers, a new set of written measures, new synthetic data sets, the Anthropic API for the two AI functions, Excel and Claude as hosts.

## Constraints

- Real companies carry real lender data and invented ownership stakes only. Invented revenue, earnings, debt or letters go on invented companies.
- Every synthetic value is marked synthetic wherever a real value shows a filing link.
- The synthetic investor, its funds and its managers are invented. Never name an organisation Alexandre is applying to.
- The two AI functions are off by default and send text to Anthropic only when the person turns them on. Synthetic letters only.
- A person confirms every event before it changes a number.
- All labels in any answer key are Claude's until a person checks them.

## Recommended decisions

Recommended by Claude on 21 November 2026, after Lender Watch merged (pull request 19). Awaiting Alexandre's approval.

| Question | Recommendation | Why |
|---|---|---|
| Monitoring or deal flow | Portfolio monitoring only | Deal flow needs documents and a pipeline that don't exist here |
| When | Now, before Lender Watch is live | The prototype runs locally on the merged code. It doesn't need the hosted sign-in |
| Where it runs | This repo, local only: the local tool server and `make excel`. Not in the hosted service | A prototype on synthetic data must never reach the hosted address |
| Synthetic portfolio | One invented investor, 8 funds of which 2 are funds of funds, 60 companies: 20 real public companies from the lender data and 40 invented ones. Generated by a script with a fixed seed, and committed | Funds of funds make look-through maths matter. Real companies keep the link to real lender stress |
| Real companies | Real lender marks, plus the invented investor's own records only: which funds hold them, its share, and what it paid | "What we paid" is a fact about the made-up investor, not about the real company. This resolves the conflict with the rule against invented figures on real companies |
| Invented companies | Invented everything: revenue, earnings, debt, the manager's value, lender marks and letters. Every value marked synthetic | Needed for debt against earnings and for the manager-versus-lenders gap |
| First 6 measures | 1. Lender value as % of amount owed. 2. Change in a quarter. 3. Our cost in companies lenders have marked down. 4. Share of our cost marked down. 5. Debt against earnings (invented companies only). 6. Gap between the manager's value and the lenders' value (invented companies only) | Two from real data, two that join real data to our records, two that need private data |
| How a measure is asked for | One more tool, `get_measure(measure, companies, as_of)`, beside `check_lenders`. Excel: `=LW.MEASURE(name, A2:A10, [as_of])` | One tool for every measure. A new measure is a new definition, not a new tool |
| Where measures live | `semantic/measures.yaml`: plain-words definition, owner, version, and the code that computes it | Matches the earlier 60-question test's design. That file wasn't found, so this starts fresh |
| Letter reader | 20 synthetic letters, with an answer key labelled by Claude. Uses `claude-opus-5-5` with structured output. Proposes events. A person confirms each one before it counts | Measures accuracy without risking a wrong number |
| Change explainer | Code splits the change into parts that add up exactly. The model only writes the sentence | No number comes from the model |
| Names | Invented names marked as such, for example "Synthetic Pension Plan" and "Synthetic Fund 3". No real firm's name | Avoids implying a real firm holds anything |

## Open questions

- **Is "what we paid" enough for the exposure measures?** It shows money at risk at cost, not today's value. Today's value for a real company would be an invented figure. If cost isn't enough, the exposure measures move to invented companies only.
- **Who signs off a definition?** A prototype has no risk team. Draft names "Alexandre (acting owner)" in each definition.
